## 1. 文档目的

本文件把已整理的 148 个仓库收口为可执行的项目组合，明确：

1. 已完成、进行中、待开发和受阻事项；
2. 当前主产品的工作范围、交付物和验收标准；
3. 教练免费开放、三角色权限、每教练 1000 个免费学员、分佣结算的实现边界；
4. 从本地可演示版本到越南服装卖家试点、再到生产发布的排期与成本模型。

**状态定义：**

- **已验证**：代码存在，并有当前测试或构建证据。
- **已实现待修复**：主要代码存在，但最新全量门禁未通过。
- **框架完成**：接口、模型或本地流程可用，真实外部服务尚未连通。
- **待开发**：尚无可验收实现。
- **待业务确认**：依赖价格、合同、账号或运营规则。

**证据边界：** 当前核心工程位于本地 `pi-kernel` 工作区；它不是 Git 工作树，因此本文件不会把本地代码描述成已提交或已推送。148 仓清单用于资产归属，不代表 148 个仓库今天都做过构建和测试。

## 3. 当前开发进度明细

### 3.1 pi-kernel 基础平台

**已验证：**

- 插件内核、服务注册、事件总线、数据总线、工作流、Cron 调度。
- 统一 `executeTool` 咽喉点、审批闸门、策略引擎、追加式审计。
- Webhook、SSE、Mailer、Agent Runtime、Agent Mesh、OpenAI 兼容网关。
- CRM 与零售插件基础能力，读操作免审批，写操作进入审批。

**当前验收结果：** 最新全量测试实际输出为 **226 passed / 1 failed**；测试输出完成后因历史监听句柄未退出，被 90 秒超时终止。失败项来自能力市场角色默认值，不是内核基础机制。

### 3.2 CRM / AutoManus 克隆

**产品定位（2026-09-29 用户明确）：**
- CRM 是个独立的 agent，定位是销售：卖能力市场的 skill、卖用户的 agent（47 张能力卡等）。
- CRM 与客户端（Target 工作台、教练客户端）没有关系，不做关联。
- CRM 不跟任何单个 agent 绑定/关联：它是独立销售 agent，不嵌入到具体能力卡里。

**已验证：**

- P0：客户、跟进、任务、渠道消息、客户时间线、MCP 数据入口。
- P1：AI 草稿；无模型密钥时可降级本地规则。
- P2：订单、售后、线索 enrichment、销售/客服/跟进 Agent 小队、多语言与时区草稿。
- A 包：Agent 训练配置、知识库、库存、CSV/TSV/XLSX 导入、知识引用草稿。

**待开发：**

- B 包：Web Chat 组件、WhatsApp 部署、基于知识库的接待闭环。
- C 包：公开 Agent 创建 API、标准 MCP Server、“需求→调研→部署”自动链路。
- 生产身份、租户隔离、配额、计费、运营后台和部署流水线。

### 3.3 店铺连接

**已验证：**

- 连接新增/更新/删除、报表导入、快照查询、RFC4180 CSV/TSV 解析。
- Token 使用 AES-256-GCM 密封；视图、事件和日志不回显原文。
- Target、Amazon 注册为已验证目录项；Wayfair、Walmart 与未知平台可登记但标记未验证。
- 写操作进入审批；21 项模块测试通过；有一键教练试用入口。

**未完成：**

- Walmart OAuth/SP-API、Wayfair 供应商 API/EDI 的真实账号联调。
- API 自动同步、Token 刷新、定时任务、快照归档策略。
- pi-kernel 本地新增功能尚未 commit/push。

### 3.4 能力市场与教练商业化

**基础能力已实现：**

- 40 张种子能力卡，覆盖卖家 7 个生命周期阶段。
- 单卡授权、收回、目录同步、审计、筛选和 Web 投影。
- 线下付款登记模式的订单状态机：`created → paid → fulfilling → settling → done`。
- 佣金账本；比例、固定金额、按人头三种计提方式。
- 7 张首批可变现卡：验货、验厂、打样、驻厂、报税、VAT 注册、学员招募。

**教练系列最新实现：**

- 三张免费卡：1:1 教练咨询、学员招募、培训课程。
- 角色继承：`coach > seller > user`。
- 用户：浏览、看详情、预约免费体验。
- 卖家：继承用户权限，并可报名课程、预约教练、查看本人订单。
- 教练：继承卖家权限，并可管理自己的卡片、学员和招募。
- 每个教练默认 1000 个免费学员名额；同一学员同一卡幂等去重；额度耗尽拒绝新免费报名并记录审计。
- 免费学员到课/有效后按人头形成待结算单；平台向教练采购交付。
- 付费订单默认教练 70%、平台 30%，支持按卡覆盖。
- 教练三张卡已打 `category=apparel`、`targetAudience=VN` 标签。

**当前缺陷，必须先修：**

1. `npm run typecheck` 当前有 3 个错误，均在 `capability-market/plugin.ts`：1 个 `dataClasses` 类型推断问题、2 个 `null` 与 `undefined` 参数不兼容。
2. 全量测试有 1 个失败：订单工具测试未传角色，默认按 `user`，而“查看自己的订单”要求 `seller` 及以上。
3. 因上述问题，教练角色/名额/分佣/越南标签只能标记为“已实现待修复”，不能标记为发布完成。

## 4. SOW 范围

### 4.1 项目目标

交付一套可运营的“能力分享销售平台”，第一阶段服务 **越南服装类电商卖家**：平台招募学员，教练负责交付；教练能力卡免费开放，每位教练可承接 1000 个免费学员；免费学员按有效人头向教练结算，付费服务按比例分佣；所有外部写动作必须审批并可审计。

### 4.2 本期包含

- 修复当前编译与测试阻断，建立可发布基线。
- 教练、卖家、普通用户三角色与对象级权限。
- 教练入驻、资料审核、能力卡发布和上下架。
- 免费名额、报名、到课/有效确认、结算、对账。
- 服装类目和越南受众的目录、搜索、推荐和运营标签。
- 越南语、英语、中文三语基础界面和通知模板。
- CRM 匹配卖家阶段，生成推送草稿；任何外发进入审批中心。
- 订单、履约、佣金和教练结算后台。
- 店铺、数据商、Agent、用户账号的 Connect 统一入口。
- 试点发布、监控、备份、隐私与安全验收。

### 4.3 本期不包含

- 未经审批的自动发信、自动私信、自动下单或自动付款。
- 未取得官方权限的 Wayfair/Walmart 生产 API。
- 未签合同的数据商生产数据。
- 第一阶段的全自动支付拆分；先保留线下付款登记和结算审核。
- 对 148 个仓库逐仓重构；仅处理主线依赖和治理计划。

## 6. 里程碑与建议排期

以下为**单个全职工程负责人 + AI 辅助**的规划估算，不是承诺日期；外部账号审核和教练签约不计入开发工期。

| 里程碑 | 估算 | 交付结果 |
|---|---:|---|

## 7. 成本模型

### 7.1 开发成本

用人日报价计算，不预设团队单价：

`开发预算 = 实际人日 × 约定单价 + 云资源 + 第三方 API + 本地化/客服`

建议先批准 M0+M1，待 100 人试点数据出来后再批准后续阶段，避免一次性锁定全部 56–98 人日。

### 7.2 每教练 1000 个免费学员的运营成本

以下只是预算模型，教练单价和越南获客价格仍须询价确认：

| 场景 | 教练课酬/人 | 获客/人 | 1000 人预算 |
|---|---:|---:|---:|
| 自然流量优先 | $2 | $0.5 | $2,500 |
| 混合投放 | $3 | $2 | $5,000 |
| 付费加速 | $5 | $5 | $10,000 |

**试点建议：** 先做 1 位教练 × 100 名学员，预算约 **$250–$1,000**。成本公式为：

`总成本 = 有效到课人数 × 教练人头价 + 获客人数 × 获客成本 + 翻译/客服 + 支付费用`

免费学员不是零成本；必须同时跟踪到课率、付费转化率、客单价、毛利和教练应付，达到单元经济性阈值后再扩到 1000 人。

## 8. 商业规则基线

### 8.1 免费学员

- 每位教练默认 1000 个免费学员名额。
- 报名成功扣减；同一学员同一卡重复报名不重复扣减。
- 名额耗尽后拒绝新免费报名，不自动转付费。
- 学员完成“有效到课”后才产生教练应付。
- 人头单价当前默认值为 0，必须由平台运营配置后才会形成实际应付金额。

### 8.2 付费学员

- 默认分成：教练 70%，平台 30%。
- 可按能力卡设置覆盖比例；各方比例合计必须为 100%。
- 退款、拒付、税费和渠道费的扣减顺序尚未定义，生产收款前必须补齐。

### 8.3 权限

| 动作 | 用户 | 卖家 | 教练 |
|---|:---:|:---:|:---:|
| 浏览/查看/免费体验 | 是 | 是 | 是 |
| 课程报名/预约教练 | 否 | 是 | 是 |
| 查看本人订单 | 否 | 是 | 是 |
| 管理本人能力卡 | 否 | 否 | 是 |
| 查看学员/管理招募 | 否 | 否 | 是 |

所有权限必须在服务端执行，前端隐藏按钮不能代替授权校验。所有外部写操作继续遵守“审批后执行”的铁律。
